\subsection{Problem}

Until post-secondary education, mathematics is almost exclusively taught using the decimal number base. Even in post-secondary, alternative number bases are scarce. This leaves a gap in foundational learning for other number bases such as octal. The octal number base is not only important for direct application in software/programming (e.g., Unix file permissions, ASCII \cite{LenovoOctal}), but it can also act as a stepping stone to introduce the concept of alternative number bases while still being relatable to decimal. At the same time, there is a significant appetite for recreational mathematics games utilizing numbers-based problem solving and puzzles (e.g., University of Calgary Recreational Mathematics \cite{UoCRecMath}).

A most perfect magic cube is a cube where each voxel's value is a distinct number from 1 to n^3 and all rows, columns, pillars, 2-dimentional diagonals, 3-dimensional diagonals (triagonals), and broken space diagonals in the cube sum to the same number, also called the magic constant. The order-eight cube is the smallest order most perfect magic cube. Using octal within this order-8 magic cube showcases the magic properties of the cube with the above prescribed lines summing to 4004, half lines summing to 2002, and the complementary numbers (+4 4 4 for the x y z coordinates from a given voxel) summing to 1001 (all in octal). These properties make the 8 x 8 x 8 magic cube in octal a perfect candidate/tool/strategy for learning/practicing addition and subtraction in octal. However, despite the clear benefits, there is a lack of resources that utilize this concept.

It is in this context that we propose an octal-base puzzle game to provide a fun and engaging means of learning and utilizing the octal number base. In this proposed game, players start with one voxel (number) in a most perfect magic cube visible with all other voxels hidden. The player must then complete tasks involving finding the voxels associated with the prescribed lines adding up to the magic constant. Each round of the game will have multiple tasks of increasing difficulty for the player to complete. This game involves much addition and subtraction which can help teach the player octal arithmetic.

\subsection{Inputs and Outputs}

The inputs of the system include:
\begin{itemize}
    \item Gameplay interactions (e.g., navigating 3D environment, selecting a voxel, etc.).
    \item Game settings and user account settings (e.g., accessibility, usernames, passwords, etc.).
\end{itemize}

The outputs of the system include:
\begin{itemize}
    \item Visualization of the magic cube and their current task progress.
    \item Indications to the user of whether their answer was correct or incorrect along with interactive hints.
    \item Updates to the local and online database of user accounts, leaderboards, and game statistics.
\end{itemize}

\subsection{Stakeholders}

A primary stakeholder is individuals looking for a game rooted in recreational mathematics. These are players who are not necessarily trying to learn octal addition and subtraction for the game, but who have an appreciation for the octal number base and enjoy intellectually stimulating, mathematical games. This is a primary user group as they will be directly playing the game.

Another primary stakeholder is high-school students who require a tool to learn the octal number base. These are players who are looking for an engaging way to learn the octal number base. This is a primary user group as they will be directly playing and learning from the game.

A secondary stakeholder is high-school teachers. These teachers would use the game as a prescribed tool to students to help them learn the octal number base. This is a secondary user group as they will not be playing the game directly but would be advising and potentially teaching the students how to use the game.

A tertiary stakeholder is post-secondary programs rooted in STEM; specifically, programs where alternative number bases are used. This is a tertiary user group because although the programs do not use the game, they benefit from new students who have a deeper understanding of alternative number bases. Through the game, players will have gained a deeper understanding of octal, and furthermore, have an idea of how alternative number bases function leading to an easier transition in these post-secondary programs.

\section{Goals}

\begin{enumerate}
    \item \textbf{3D Visualization of Game Space:} Allow user to rotate, zoom, and move through the layers of the cube. Also, use highlighting to differentiate the slices and selected blocks. This goal can be measured through functional testing to see if the 3D space can be visualized and navigated as intended (i.e., can the user move through the 3D space with the functions provided by the game). Additionally, user observation would be used to measure the intuitiveness of the navigation controls and visualization techniques (e.g., time to perform a certain action, improvement of navigation over time, etc.).
    \item \textbf{Guided Gameplay Learning and User Tutorial:} Game explains mistakes users make while playing the game and if requested, shows them the path/workflow to the correct solution. This can be measured through user testing where behavior such as time to complete a task, relative performance (score and/or time) before and after game explains mistakes, etc. Additionally, the game provides an interactive tutorial to teach the user how to play the game. This goal can be measured by user performance (score and/or time) before and after using the interactive tutorial.
    \item \textbf{Online Competitive Mode:} Track and document game statistics, provide daily tasks/challenges with a sharing results feature, showcase leaderboards, and create / allow access to user accounts. This goal can be measured using functional testing to ensure that all these features are working as intended as well as user testing to assess the added value of the features from the player perspective.
    \item \textbf{Mathematically Educational:} Ensure game is useful in helping users learn about addition and subtraction in alternative number bases (not decimal). This goal can be measured through user testing by tracking how well the users can perform octal addition and subtraction before and after playing the game.
    \item \textbf{Task-Based Problem Solving:} Provide players with tasks utilizing the prescribed lines. The tasks will increase in difficulty as the player progresses through the round. Furthermore, the tasks should be different each round. This goal can be measured using functional testing to ensure that the gameplay correctly implements these functionalities as well as user testing to measure how intuitive the gameplay is (e.g., player survey or behavior observation).
    \item \textbf{Fun and Engaging:} Ensure the game is fun and engaging for both learners and recreational players. This goal can be measured through user testing with user interviews, amount of time the user is focused solely on game (user observation), etc.
\end{enumerate}

\section{Stretch Goals}

\begin{enumerate}
    \item \textbf{Different Game Bases / Family of Games:} Expand game to other number bases (e.g., decimal, dozenal). Additionally, expand game to magic squares (2-dimensional version of magic cubes). Furthermore, the game could go up to the fourth dimension, however this would require extensive user testing to figure out and measure how to intuitively present the game space and objectives.
    \item \textbf{Variations on Ruleset and/or Objective:} Expand game to slightly different game modes with different rules and objectives. For example, a game with a magic square where instead of trying to find a specific line, the user must fill the numbers of a partially complete magic square to make it whole. This goal can be measured with user testing to evaluate the effectiveness of different game modes on user enjoyment and education value as well as functional testing to ensure the game modes are working as intended.
    \item \textbf{Additional Mathematical or Algorithmic Analysis:} Automatically generate new formations of magic cubes (i.e., not just shuffling the same magic cube formation, but creating a new one entirely). This goal can be measured with functional testing to ensure it is working as intended as well as user testing to measure the change in user value with this additional functionality.
\end{enumerate}
